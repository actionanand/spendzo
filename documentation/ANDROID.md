# Android build and release

Spendzo's Android project is generated by Capacitor in CI and then patched with native behaviour
from `scripts/patch-android.mjs`. Generated `android/` files and signing credentials are deliberately
not committed.

## Local WSL2 setup

After installing the dependencies listed in the main handoff, run:

```bash
npm run build
npx cap add android
npx cap sync android
npm run android:patch
```

Open the generated project in Android Studio or run Gradle from `android/`.

## Versioning

The Android `versionCode` and `versionName` live in `android-version.json`. Bump them with:

```bash
npm run android:version:patch
npm run android:version:minor
npm run android:version:major
```

Every command increments `versionCode`. The selected command also updates semantic
`versionName`.

## What the native patch provides

- SQLite storage behind the `SpendzoDatabase` repository bridge.
- Android Keystore-backed biometric secret storage.
- Strong fingerprint authentication with PIN fallback.
- Edge-to-edge system bars without white top or bottom segments.
- White system-bar icons in dark mode and dark icons in light mode.
- Android 12+ `Theme.SplashScreen` styling.
- The `public/spendzo.png` asset as launcher and splash artwork.
- Gradle version information from `android-version.json`.

Run `npm run android:patch` again after every `npx cap sync android`.

## GitHub Actions

`.github/workflows/android-build.yml` runs lint, unit tests, the Angular production build,
Capacitor synchronisation, native patching, Java setup, and Gradle.

- Branches and pull requests produce a debug APK.
- tags matching `v*` produce a signed APK and AAB.
- Outputs are copied into `release/`, uploaded as workflow artifacts, and attached to a GitHub
  Release for version tags.

Configure these GitHub Actions secrets:

| Secret                      | Purpose                                             |
| --------------------------- | --------------------------------------------------- |
| `ANDROID_KEYSTORE_BASE64`   | Base64-encoded JKS/PKCS12 keystore                  |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password                                   |
| `ANDROID_KEY_ALIAS`         | Signing alias, `spendzo` for the included generator |
| `ANDROID_KEY_PASSWORD`      | Key password                                        |

Never commit the keystore or passwords.

## Generate a signing keystore

Run in WSL2:

```bash
npm run generate-keystore -- --password 'YOUR_STRONG_PASSWORD'
# or
npm run generate-keystore
npm run keystore:type
base64 -w 0 spendzo-release.jks > spendzo-release.jks.base64
```

Store the original keystore and passwords in a durable secure location. Android app updates must
be signed with the same key.

## Release

1. Bump `android-version.json`.
2. Commit and push the version change.
3. Tag the same version, for example `v1.0.1`.
4. Push the tag.
5. Download the APK/AAB from the workflow's `release/` artifact or the generated GitHub Release.
